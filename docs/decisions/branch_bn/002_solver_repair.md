# BN002：同一首轮中的数值求解修正

在最终测试库尚未评价时，模型302增强读出的 C=1 候选在 L-BFGS 3000 和15000次迭代后仍未收敛。原日志、失败文件和301已完成拟合的部分记录保存在 `artifacts/branch_bn/round1/attempts_lbfgs/`。301的进行中诊断被中断，以统一修正求解流程；不是科学实验结案。

本地 sklearn 源码 `_logistic.py` 明确给出：lbfgs 与 newton-cholesky 使用相同的 `l2_reg_strength=1/(C*sum(sample_weight))`。因此改用显式 Hessian 的 Newton-Cholesky 求解**相同**加权逻辑回归目标，不改特征标准化、样本、标签、权重、C 网格、验证选择、噪声或科学阈值。

所有五模型、两个主头、数量探针和学习曲线统一使用该求解器；不按测试效果选择求解器。设置 tol=1e-7、max_iter=200，必要时1000；保留所有警告与迭代记录。若仍不收敛继续数值审计，不判为机制失败。

启动前先验证：加权小型问题上两个求解器目标／预测一致；真实失败模型302、真实增强拟合数据上 C=1 的解析平均目标梯度达到数值精度。最终审计另核对全部候选收敛及选中C。首次失败是实现／求解限制，不计作假设反证；原失败不会被删除或改写。
